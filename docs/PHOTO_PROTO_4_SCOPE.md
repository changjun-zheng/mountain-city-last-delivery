# 摄影原型第 4 轮：范围、状态与取舍（2026-11-22）

## 用户补充需求（2026-11-22 原文归类）

**动态环境**

- 河水要流动，流动自然、符合物理逻辑；江面偶尔出现船。
- 天空要有飞鸟，不必具体但不能夸张；不要老鹰，可接受白鹭一类，最好是重庆本地常见鸟类。
- 街上可出现重庆特色黄色出租车（用户原话“黄色法拉利”）；其他车辆参考主流车型与动漫用车，但不得露出车牌号与具体型号（侵权风险）。
- 加入时间变化（清晨、凌晨、黄昏）与天气变化（下雨、打雷）。

**交互**

- 进入房屋：门关时需要有开门动作，门开时可直接进入。
- 视角转换、与 NPC 对话、观看表演；大场景中可有休闲玩法（喝水等）。
- 旅游景点处应有多名游客与其他景点交互。

**美术与角色**

- 游客角色重新绘制，分男女；有条件时增加服装选择与脸型选择。
- 角色动作随地形变化，符合正常运动与物理逻辑。

**场景**

- 全部替换，以真实重庆为主要依据。

**系统**

- 冒险向收集品：不同角色获得不同收集物。
- 每个场景有对应的特定地图。

**交付方式（用户明确指令）**

- 今天给出可玩效果较好的版本，明天验收。
- 由主指挥窗口自行开浏览器验收、发现问题自行修改并持续迭代。
- 每完成一个较小功能即提交并推送 GitHub。
- 遇到问题多联网搜索，多去 GitHub 找资源。

## 技术判断

上述清单无法在一天内全部完成。若一次性全上，每个系统都会停在半成品状态，整体可玩性反而低于现在。当前策略是先保证「走得动、看得下去、拍得成」的主循环成立，再按上表顺序逐项叠加，每项独立提交。

现有架构（Phaser 3 + 整图烘焙底图 + 分层室内地图）已经支持后续叠加：动态元素走 `front` 绘制层与屏幕层；时间/天气可用色调叠加与粒子；NPC 与门交互可复用探索章节已有的对话与门触发器机制。
