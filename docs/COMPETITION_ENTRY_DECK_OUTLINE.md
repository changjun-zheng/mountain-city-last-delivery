## 0. 这份说明书要达成的三件事

1. 评委在第 2 页就知道这游戏是什么、玩什么、为什么特别
2. 每一页都有一张能单独拿出去当封面的图
3. 看完相信这是个能跑起来的作品，不是一个概念

## 1. 页面骨架（16 页）

### P1 封面

- 主标题：《坡坎之间》
- 副标题：一款在重庆山城找机位拍照的探索小游戏
- 主图：蓝调时刻的吊脚楼全景，红灯笼与江面倒影
- 角标：2026 首届重庆市小游戏创新创业大赛 · 渝你同行特色赛道

### P2 一句话 + 三张图

- 一句话：**你是第一次来重庆的游客，茶馆老人给你一张手写清单，你要在黄昏到入夜之间，找到那些只有本地人才知道的机位。**
- 三张并排图：亮灯的吊脚楼 / 蓝调时刻的江面 / 相册页
- 这一页决定评委要不要继续看，不放任何技术信息

### P3 创意来源：机位是重庆的在地知识

- 真实机位举例：洪崖洞要 19:30 亮灯后去 1 楼马路对面；李子坝要赶 8 点前占观景台最左侧玻璃缺口；长江索道要坐日落前那班、上车直奔车尾右侧
- 论点：**这套知识不是攻略，是一套可被规则化的空间—时间—构图组合题**
- 配图：一张真实重庆夜景照片（标注“仅作构图参考”）＋ 一张游戏内同角度截图

### P4 核心循环

- 循环图：拿清单 → 找机位 → 等光 → 取景 → 评分 → 相册 → 解锁
- 一句话解释每一环
- 配图：四个小图标横排

### P5 机位清单

- 12 个机位的分布图：上街 4 个、中街 4 个、下街 2 个、江岸 2 个
- 主线 6 个（有提示）／隐藏 6 个（无提示）
- 配图：分层地图 + 机位标记

### P6 评分与时段

- 三档评分：铜（入框）／银（构图）／金（时机）
- 四档时段：黄昏 → 亮灯 → 蓝调 → 入夜
- 重点讲蓝调 90 秒窗口：**唯一的紧迫感，也是重玩的理由**
- 配图：同一机位四个时段的四宫格对比

### P7 创新点一：把“机位”做成玩法

- 普通拍照游戏是“看到什么拍什么”，本作是“必须站在这里、等这个时刻、框成这样”
- 它把重庆的摄影文化变成了可判定的规则，这是**只有重庆能长出来的机制**
- 配图：正确构图与错误构图的对照（带评分提示）

### P8 创新点二：一条清单串起一座垂直城市

- 同一栋吊脚楼，从下街仰拍、从中街平拍、从上街俯拍，是三张完全不同的照片
- 玩家的动线不是“逛地图”，是“爬一座立体的城”
- 配图：同一建筑三个高度的三张截图上下排列

### P9 创新点三：十分钟一局，带走一本相册

- 通关即生成“重庆印象”相册，可分页、可调色、可加边框贴纸
- 结束时玩家的收获不是“通关”，是“我拍了一本相册”
- 配图：相册页实拍（九宫格 + 档位角标）

### P10 美术风格

- 手绘感 + 赛璐璐结构：结构用硬边保证平台与路径可读，表面叠水彩纸纹与笔触
- 日间暖黄市井，夜间深蓝加霓虹
- 季节：夏末绿 → 深秋黄，一次过渡
- 配图：同一场景的夏／秋两版对照

### P11 技术实现

- Phaser 3.90 + TypeScript + Vite，纯前端，浏览器直接运行，不依赖后端
- 桌游键盘／手机虚拟摇杆双端
- 拍照评分是纯几何与时间判定，不依赖图像识别，保证性能与稳定
- 配图：架构简图（场景层 / 玩法层 / 数据层）

### P12 内容规模

- 12 个机位、4 个时段、2 个季节、4 类图鉴、1 段索道
- 主线 10 分钟，全内容 35—40 分钟
- 明确写“这是可玩 Demo，不是完整商业版”

### P13 目标用户与场景

- 来重庆的游客（出发前预热、旅途中打卡对照）
- 本地年轻人（找机位、发照片）
- 文旅场景：景区导览、城市宣传的轻量载体

### P14 团队与制作方式

- 团队构成（按实际填写：人数、角色）
- 制作方式：AI 辅助开发，人负责玩法决策与验收
- 如实说明 AI 参与范围，不夸大也不隐瞒

### P15 后续规划

- 短期：补齐 12 个机位的美术、加音效、手机真机适配
- 中期：增加机位（李子坝轻轨穿楼、长江索道车厢、佛图关列车）
- 长期：做成可更新的“重庆机位地图”，按季节与节日更新内容
- 明确写清哪些是本版没做的（战斗、多关卡、云存档）

### P16 结尾

- 一句收尾文案 + 联系方式
- 留一张最有冲击力的图满版

## 2. 三个必截图镜头（视频与 PPT 共用）

这三个镜头决定评委的第一印象，必须在实机里真的拍出来，不能用概念图代替。

### 镜头一：亮灯瞬间

- 时机：完成 M1 后触发 T1，灯笼逐一点亮的那 2 秒
- 机位：H3 上街边缘，镜头略低，吊脚楼占画面上三分之二
- 要的效果：画面从灰暗变暖黄，红灯笼像被点燃一样次第亮起
- 用途：视频开头、P2 三图之一、P7 对照图

### 镜头二：蓝调时刻

- 时机：T2 窗口内
- 机位：M5 江岸，镜头平视，江面倒影占下三分之一
- 要的效果：深蓝天、暖黄灯火、水面完整倒影，三者同框
- 用途：封面主图、P9 相册页背景

### 镜头三：相册页

- 时机：通关结算后
- 机位：UI 全屏，九宫格照片墙 + 档位角标 + 一句收尾文案
- 要的效果：一眼看懂“我拍了 12 张照片”
- 用途：P2 三图之一、P9 主图、视频结尾

## 3. 演示视频脚本（3 分钟以内）

| 段落 | 时长 | 内容 |
| --- | --- | --- |
| 开场 | 0:00—0:15 | 黑屏出游戏名，直接切亮灯瞬间 |
| 说明 | 0:15—0:45 | 一句话讲清“游客 + 清单 + 机位”，配分层地图 |
| 演示 | 0:45—2:00 | 完整走一遍：找机位 → 等光 → 取景 → 出分 → 上相册。中间穿插一次失败重拍 |
| 高潮 | 2:00—2:30 | 蓝调时刻拍江面倒影，出金档 |
| 收尾 | 2:30—2:50 | 索道过江 + 相册全页展示 |
| 落版 | 2:50—3:00 | 游戏名 + 团队名 |

要点：全程实机录屏，不解说技术参数，只讲“玩家在做什么、为什么想再试一次”。

## 4. 答辩预设问题

| 可能被问 | 建议回答方向 |
| --- | --- |
| 和普通拍照游戏有什么区别？ | 普通拍照是“看到就拍”，我们是“必须站在对的位置、对的时间、对的构图”，有明确判定，是可玩的规则而不是滤镜 |
| 为什么一定要是重庆？ | 机位这套知识是重庆独有的：垂直高差、穿楼、两江夜景，换一个平坦城市这套机制就不成立 |
| 十分钟是不是太短？ | 主线 10 分钟是给评委的完整体验，全部内容 35—40 分钟；这类探索游戏靠密度不靠时长 |
| 团队几个人？ | 按实际回答，如实说明 AI 参与开发的协作方式 |
| 后续怎么商业化？ | 文旅导览、景区联名、按季节更新机位内容；不承诺未验证的商业模式 |
| 美术是谁做的？ | 如实说明：结构由程序化绘制保证可读性，视觉素材由 AI 生成并经人工筛选调整 |
