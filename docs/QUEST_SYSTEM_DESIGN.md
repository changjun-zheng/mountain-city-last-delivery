## 任务自动接取机制

状态：CONFIRMED。

确认日期：2026-11-06。

依据：项目负责人本次明确指示。决策记录见 [DECISIONS.md](DECISIONS.md)。

1. 游戏采用自动接取任务机制。
2. 玩家主动与发布任务的 NPC 互动。
3. 玩家了解 NPC 的委托内容后，任务自动接取。
4. 不额外显示“接受任务”和“暂不接受”选择框。
5. 接取成功后，任务自动加入任务列表。
6. 系统向玩家显示新任务提示。

触发边界：玩家仅仅靠近 NPC 不会自动接取任务，必须主动交互并触发相应对话流程。这里的“自动”指了解委托后无需额外确认接取，不表示靠近即接取，也不确定具体交互按键。

任务列表和新任务提示的存在已确认；任务追踪的组合方向见下节，具体界面布局、追踪规则和操作方式尚未确定。

## 任务追踪设计方向

状态：CONFIRMED。

确认日期：2026-11-06。

依据：项目负责人本次明确指示。

1. 采用实时任务提示 + 独立任务日志的组合方案。
2. 游戏过程中显示简洁的当前任务目标。
3. 任务日志用于保存已接取任务和完成记录。
4. 任务目标完成后自动更新。
5. 不直接显示完整谜题答案。
6. 优先通过场景线索引导玩家探索和解谜。

确认范围为上述组合方向与呈现、引导原则，不包含具体追踪规则、UI 布局或操作方式。“当前任务目标”不等于已确定同时显示目标的数量；“自动更新”不等于已确定默认追踪或自动切换任务规则。任务日志保存记录也不等于已确定跨会话存档或检查点恢复方式。

状态：CONFIRMED。

确认日期：2026-11-06。

依据：项目负责人本次明确指示。

## 收藏品、任务目标、奖励与永久效果的唯一 ID 和幂等规则

状态：CONFIRMED。确认日期：2026-11-07。依据：项目负责人本次明确指示。

- 每个收藏品、每个任务目标、每份奖励都具有稳定唯一 ID；永久世界效果具有独立唯一 ID，各类型 ID 保持自身业务身份，不得混用。
- 重复触发同一收藏品不得重复获得；重复完成同一目标不得重复记录；重复奖励事件不得重复发奖。
- 重复应用同一永久效果不得产生错误的反向变化；不能把重复应用当作将永久效果打开、关闭的切换操作。
- 检查点恢复不得清除上述永久记录，场景对象应根据永久记录重新同步。

永久进度与临时世界状态分离。已完成任务目标永久保留，对应的永久世界效果优先于快照；普通临时机关仍按快照恢复，之后重新应用永久效果。这不将所有机关状态升级为永久。首关 MVP 主线接取及 C 区完成状态按下方冻结规则保留；其他任务的接取与进行中状态仍需分别设计。

### PROPOSED：永久记录的数据分类

| 建议分类 | 业务身份 |
| --- | --- |
| `collectedItemIds` | 已获得的收藏品 ID |
| `completedObjectiveIds` | 已完成的任务目标 ID |
| `claimedRewardIds` | 已领取的奖励 ID |
| `permanentEffectIds` | 永久世界效果 ID |

以上仅为分类建议，未确定最终字段、容器或跨会话存储方式；ID 不能因一次事件同时产生多类结果就混为同一业务身份。

备用检查点完整快照结构已确认（CONFIRMED，2026-11-07）：与正式检查点共用结构和恢复机制；初始化场景、临时机关和平台后，先加载并应用已有永久进度及永久效果，再记录安全出生位置、捕获登记范围内临时状态并登记备用检查点，完成后才开放玩家控制。永久收藏、已完成目标、已领取奖励和永久效果不进入临时快照，恢复时先恢复临时世界，再重新应用永久效果。快照只记录登记对象的逻辑状态，不复制整个世界或物理引擎内部对象，静态建筑、背景与装饰物不参与。

第一版只保留一个当前有效检查点及其完整临时快照已确认（CONFIRMED，2026-11-07）：激活其他正式检查点时替换；离开保留、重入刷新、持续停留不重复捕获；返回旧检查点重新捕获当前世界，不保留可恢复的历史快照。永久进度、永久世界效果及唯一 ID 幂等记录仍独立管理，不因快照替换而回滚。

恢复阶段事件规则已确认（CONFIRMED，2026-11-07）：Failure / Recovery 屏蔽坠落与检查点事件处理，物理碰撞不整体关闭；单一恢复流程，重复事件不重复淡出/恢复/传送；结束前重算占用，恢复传送与重启不生成虚假进入，相关区域须真实离开再进入才产生新有效事件。

原子快照捕获已确认（CONFIRMED，2026-11-07）：先提交请求，在同一指定安全模拟边界捕获登记对象的逻辑状态，不在物理碰撞回调内捕获；独立候选快照完成对象 ID、完整性及结构验证后才替换有效快照，失败保留原快照，初始备用快照失败不开放探索。永久记录仍独立管理。

固定快照登记清单已确认（CONFIRMED，2026-11-07）：初始化时登记稳定唯一 ID 的快照对象，第一版不任意动态注册注销，隐藏/禁用/停止不删除登记；清单重复 ID、遗漏或无效数据时不开放探索。各业务永久 ID 与临时快照对象身份保持各自含义。

失败关闭式恢复已确认（CONFIRMED，2026-11-07）：必要对象、快照验证、恢复、永久效果应用或世界一致性验证出错均不得开放控制；保留原有效快照和全部永久进度，继续锁定及屏蔽坠落/检查点事件，尝试重建后重应用原快照与永久进度并重新验证。不强行解锁，也不无限自动重建；奖励、收藏品与永久效果继续遵循唯一 ID 及幂等规则。

两阶段世界恢复已确认（CONFIRMED，2026-11-07）：先恢复临时逻辑并重新应用永久进度与效果，形成最终逻辑，再重建物理与视觉；两阶段不播放普通机关操作动画，验证成功后才进入玩家恢复，失败按 Fail-Closed 处理。

固定安全恢复锚点已确认（2026-11-07）：使用备用锚点不得改变当前检查点 ID、快照和永久进度；玩家放置前在重建后的世界验证锚点安全，不因锚点切换重发奖励或清除目标记录。

锚点预设顺序已确认（2026-11-08）：先主点再按关卡顺序验证备用点，首个安全点用于恢复，全部失败进入 RecoveryError，不扫描未知位置；配置独立于临时快照，备用点不改变检查点 ID、快照和永久进度。

世界一致性验证分级已确认（CONFIRMED，2026-11-08）：玩法逻辑、永久进度、物理碰撞、路线、玩家安全、触发器错误，以及误导路线/机关/危险判断的视觉错误均为 Critical Error，阻断恢复并执行 Fail-Closed，保留永久记录与原有效快照。不影响玩法的纯装饰和环境表现异常属于 Warning，可以记录但不阻断恢复，不得误当关键错误。

RecoveryError 处理已确认（CONFIRMED，2026-11-08）：正常恢复失败后允许一次自动完整重建，重建成功后重新执行世界一致性验证，自动失败后停止自动重试、进入 RecoveryError 并显示错误界面，玩家可选择手动重试或返回标题界面。失败期间始终锁定控制，保留原当前检查点 ID、完整快照、全部永久进度和永久效果数据，不覆盖原有效快照、不强行解锁；收藏品、目标、奖励及永久效果继续遵循独立 ID 和幂等规则。

反复主动重试已确认（CONFIRMED，2026-11-08）：手动重试无固定次数上限，每次使用原当前有效快照执行完整恢复，不从失败步骤继续、不重新捕获或覆盖快照、不触发额外自动完整重建，失败后返回 RecoveryError。同一时间只允许一个恢复流程，失败期间保持控制锁定；永久进度和永久效果保留，完整恢复继续按既有规则重新应用，避免重复领取收藏品或奖励。

待确认：错误报告编号、界面细化、返回标题后的运行时数据保留及跨会话存档；完整五阶段、完整重建的具体对象边界与顺序、独立恢复接口、普通世界暂停；具体锚点、静态支撑优先、跨次验证重置与自动提升限制；独立验证器、只检查不修复、报告字段、两次验证及覆盖范围等七项验证架构提案；对象细节和安全边界。自动重建最多一次、手动重试不增加自动额度已确认。字段候选仍为提案，见 [PLAYER_CONTROL_DESIGN.md](PLAYER_CONTROL_DESIGN.md) 和 [DECISIONS.md](DECISIONS.md)。

## 首关 MVP 主线任务与通关

状态：CONFIRMED。确认日期：2026-11-09。依据：[Hongyadong First-Level MVP Design Freeze](DECISIONS.md)。

唯一必做主线为《把山城夜景寄给远方》。主角帮助年轻游客寻找合适的夜景观赏位置，并记录、分享山城记忆。A 区出生与教学后前往 B 区；玩家在 B 区主动和年轻游客对话并了解委托，自动接取主线，任务加入列表并显示新任务提示。靠近不触发接取，不显示接取或拒绝弹窗。

| 任务逻辑状态 | 转换条件与结果 |
| --- | --- |
| 未接取 | 尚未完成 B 区委托对话；完成对话并了解委托后自动进入已接取。 |
| 已接取，进行中 | 在 B 区观察唯一核心环境线索，在 C 区判断并正确操作唯一机关控制装置，启动升降平台并开放 D 区主线路线。错误可重新观察与重试，无永久惩罚。 |
| 已完成 | 主线已接取、C 区机关成功操作、升降平台路线已开放，且玩家到达 D 区指定夜景观赏位置并成功完成拍摄与分享互动。永久记录完成，展示首关完成反馈。 |

单纯到达 D 区不会完成任务。支线、额外收藏或隐藏挑战均不作为通关条件。表中是玩法状态，未指定实现枚举；具体对白、线索、交互表现与奖励内容仍为 PROPOSED。

### 首关失败后的任务状态

- 已接取主线、已完成目标、C 区机关完成、升降平台路线解锁、奖励发放记录、文化收藏品（如后续启用）和主线完成均作为永久进度保留。
- 尚未完成的机关操作、平台当前运动位置／阶段和 NPC 临时对话等按既有临时状态规则恢复或清理；临时对话不改变已接取状态。
- 使用既有检查点恢复，先还原临时世界逻辑，再应用永久效果，按两阶段规则重建、验证后开放玩家控制。已完成目标不得回退，C 区无需重新解谜，永久开放路线必须仍可通行；旧触发事件不重放，同一已发放奖励不重复发放。
- 首关可使用初始出生备用检查点，额外正式检查点位置不是设计冻结前置条件。永久进度的保留不代表已决定跨会话存档。

### 扩展内容与恢复分类

- 已获得收藏、已完成支线及实际奖励记录若未来启用，按现有永久进度原则保留，重复拾取／交还／恢复不重复发放。这里的永久不是跨会话持久化承诺。
- 玩家位置／速度、平台瞬时位置／阶段及其他已登记可回滚世界状态属于临时状态；未完成招牌交付／持有状态如何处理仍 PROPOSED，不擅自定成永久或回滚丢失。
- 先恢复临时世界逻辑，再应用永久效果，经既有重建／验证、安全放置和控制开放流程；机关已完成时 D 路线仍开放，平台必须安全可再次使用，不要求重新解谜。安全停靠点和物理坐标待确认。
- 文化观察是否记忆、后续新增 NPC／物件快照归属等未定，不把“看过 C-OBS-01”作为任何主线进度条件。

本节与 V2 拓扑／连通／无捷径验证均未执行，不能标 PASS；具体实现与排期待负责人确认后再进入唯一路线图，不改变当前开发里程碑。

## 重庆文化融入原则与洪崖洞探索方向

状态：项目设计原则为 CONFIRMED（2026-11-06）；具体任务、区域及收藏配置为 TO_VALIDATE。

以重庆真实地标建筑为重要美术参考，尽可能保留真实外观、空间结构与地域特色，允许为 2D 横版玩法进行合理空间压缩及游戏化改编。将历史、建筑文化、民俗、方言与非遗自然融入探索、任务、NPC 互动和收藏，让玩家主动发现文化，避免只阅读大量说明文字。文化历史介绍须有可靠资料依据；不将虚构机关、道路或设施描述为真实存在。

洪崖洞记录建筑探索、历史探索、重庆生活与方言探索、隐藏区域探索、文化收藏探索五类方向，不等于确认五个区域或具体互动玩法。建筑参考重点、当前景区 2006 年建成开业的资料边界及官方来源核验状态见 [HONGYADONG_LEVEL_DESIGN.md](HONGYADONG_LEVEL_DESIGN.md)。不得将当前景区整体描述为未经改造的古代建筑。
