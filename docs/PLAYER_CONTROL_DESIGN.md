# Player Control System

玩家控制系统设计文档

项目：Mountain City: Last Delivery（山城有路：最后一单）

更新及确认日期：2026-11-06。依据：项目负责人本次文档维护指示。

## 状态与设计边界

| 状态 | 含义 |
| --- | --- |
| CONFIRMED | 已经项目负责人正式确认 |
| PROPOSED | 候选设计，尚未正式确认 |
| TO_VALIDATE | 待验证或待详细设计，不能直接作为最终实现要求 |

本文中的所有数值均为 TO_VALIDATE 初始测试参数，不是最终游戏参数。确认记录见 [DECISIONS.md](DECISIONS.md)，项目概述见 [PROJECT_BRIEF.md](PROJECT_BRIEF.md)。

CONFIRMED：游戏采用 2D 横版视角；不设置传统战斗系统。既有平台跳跃、场景探索、环境解谜的核心玩法及小型半开放关卡结构保持有效。

### CONFIRMED：第一版输入方式与失败规则

确认日期：2026-11-06；依据：项目负责人最新明确指示。

- 第一版采用键盘作为游戏内主要操作方式。
- 鼠标用于菜单和 UI 点击。
- 暂不优先支持游戏手柄和手机触屏；这不等于永久排除后续支持。
- 不设置生命值系统。
- 不限制玩家复活次数。
- 不设置传统战斗系统。
- 环境挑战失败后，恢复最近一次激活的检查点快照。
- 指定检查点区域采用进入后自动激活的方式。

输入设备分工已确认，具体键位仍为待验证方案。无生命值、无限复活不改变检查点快照恢复规则，也不提前确定具体环境失败触发条件。

## 1. 移动系统 Movement System

### PROPOSED：键盘操作方案

以下整套映射均为 PROPOSED / TO_VALIDATE 候选，不是最终按键方案；键盘作为主要操作设备本身已确认。

| 按键 | 候选动作 |
| --- | --- |
| A / 左方向键 | 向左移动 |
| D / 右方向键 | 向右移动 |
| Space | 跳跃 |
| E | 互动 |
| Esc | 暂停 |

### PROPOSED：移动手感

- 移动采用轻微加速、快速减速。
- 空中允许左右控制。

### TO_VALIDATE：初始测试参数与未定细节

| 项目 | 初始测试参数（非最终值） |
| --- | --- |
| 加速时间 | 0.15～0.25 秒 |
| 空中控制能力 | 70%～85% |

移动速度、减速数值和空中控制百分比的计算基准尚未确定；不能将百分比直接当作最终物理实现定义。

## 2. 跳跃系统 Jump System

### PROPOSED：跳跃规则

- 单次跳跃，不设置二段跳。
- 支持可变跳跃高度；按键时长与高度之间的具体关系待验证。
- 加入土狼时间：离开平台边缘后，短时间内仍允许起跳。
- 加入跳跃缓冲：落地前短时间输入跳跃，可在满足起跳条件时生效。

### TO_VALIDATE：初始测试参数

| 项目 | 初始测试参数（非最终值） |
| --- | --- |
| 土狼时间 | 100～120 ms |
| 跳跃缓冲 | 100～150 ms |
| 跳跃高度 | 2～2.5 个角色高度 |
| 跳跃距离 | 3～4 个角色宽度 |

角色尺寸的测量基准、跳跃距离的测量条件、重力及起跳速度均待确定。以上范围用于后续试玩校准，不能据此锁定最终关卡间距。

## 3. 交互系统 Interaction System

### PROPOSED：统一交互

- 使用统一的 E 键交互机制。
- 存在多个交互对象时，按照角色朝向和距离选择目标。

### TO_VALIDATE：交互细节

交互范围、朝向与距离的优先关系、同等条件下的目标选择，以及交互反馈方式均待详细设计。本次不新增交互对象或任务内容，也不将既有“推拉”等能力候选改为正式决策。

## 4. 碰撞系统 Collision System

### PROPOSED：碰撞设计

- 角色视觉图片与物理碰撞体分离。
- 楼梯优先采用台阶式碰撞结构。
- 第一版使用 Phaser Arcade Physics 作为候选物理实现方案。

### TO_VALIDATE：物理实现边界

碰撞体尺寸、台阶尺寸、楼梯通行表现及移动平台的碰撞行为均待验证。台阶式结构与候选物理方案的适配效果尚未验证。

Phaser Arcade Physics 仅为候选；本条不代表已锁定 Phaser 3 或整体技术栈，也不确定任何依赖版本。文档记录不构成安装依赖或开发代码的授权。

## 5. 检查点系统 Checkpoint System

### CONFIRMED：自动激活与快照恢复

- 检查点采用快照恢复方式。
- 玩家进入指定检查点触发区域时自动激活。
- 激活后保存当前关卡状态。
- 玩家失败后恢复到最近一次激活的检查点快照。
- 环境挑战失败后同样按上述规则恢复；不设置生命值系统，不限制玩家复活次数。

确认的是上述规则；检查点快照的完整字段和临时状态的具体处理仍待验证。无生命值系统已由最新指示正式确认，具体环境失败触发条件仍为 TO_VALIDATE。

### TO_VALIDATE：快照字段

| 候选字段 | 拟记录内容 |
| --- | --- |
| 当前区域 ID | 激活快照时所在区域 |
| 玩家重生位置 | 恢复玩家所需的位置 |
| 已完成任务 | 快照时的任务完成进度 |
| 已收集关键线索 | 快照时已获得的关键线索 |
| 已解开的主要谜题 | 快照时的主要谜题完成状态 |
| 已开启的主要机关 | 快照时的主要机关开启状态 |

这些只是待验证字段，不是已确定的数据结构或存储方案。

### PROPOSED：恢复时重置的临时场景状态

- 当前对话状态。
- 当前跳跃状态。
- 临时动画状态。
- 临时移动平台状态。

上述重置方案均待验证；具体重置值和恢复顺序尚未确定。

### TO_VALIDATE：关卡进度与临时状态边界

任务、关键线索、主要谜题与主要机关拟作为需要在快照中记录的持续性关卡进度；对话、跳跃、动画和临时移动平台状态拟作为恢复时重置的临时场景状态。分类及具体覆盖范围仍待验证。

“持续性关卡进度”不表示自动保留检查点激活之后产生的新进度，也不表示已确定跨关卡或跨游戏会话的永久存档；正式规则仍是恢复最近一次激活的快照。主要机关与临时移动平台状态之间的归属需要结合具体场景核对。

### TO_VALIDATE：尚未确定的检查点细节

- 检查点位置、数量及触发区域范围。
- 首次激活检查点前失败的处理方式。
- 重复进入同一检查点时的快照更新规则。
- 跨区域及关卡切换时快照的适用范围。
- 失败判定条件与具体恢复流程。
- 检查点快照的完整字段及其覆盖范围。

上述均为待设计问题，本次不提前选定处理方案。
