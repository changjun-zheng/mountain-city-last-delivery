## V3-1. 本次重构的结论

转为 **2D 斜俯视、八向地面移动的非战斗山城探索冒险**。玩家实际进入室内，通过观察、找物、推理用途、解锁通路推进主线，选做重庆地域收藏、点亮图鉴／纪念册和成就。类似《元气骑士》的只是观察视角，不迁移为 3D 第三人称或复制其战斗。

## V3-3. 如何支撑真正的探索内容

首章不是“每个景点一张图标”，而是有可行走街面、建筑入口、室内对象、楼层通路与可回访状态的片区。详细布局只写在关卡主文，当前不冻结像素或路程。

已确认的夜景委托下，候选节奏为：街区观察与委托建立→室内找物→物品用途推理与通路解锁→江岸定位／拍摄分享收尾。关卡主文已给出路标／便笺识路、室内找导览信息、对应楼层入口使用道具、按桥／水／吊脚楼要求找取景点的具体候选。它们仍须内容评审，每节点要有可观察线索、用途、错误反馈、世界变化及提示分级；不能把三四句对白或随地按钮当完整节点。

文化收藏、主线关键物品、成就奖励分别管理：主线关键物品解释用途，文化收藏提供发现与记录，奖励反馈不增加强制全收集门槛。文化名称／图案／说明后续核验真实来源，原创谜题／设施标明游戏虚构，不编造重庆历史。完整图鉴和货币系统不是必要前置，先做可读的简单记录与一个明确奖励反馈。

玩家可以先进入已开放房间、调查不按固定顺序出现的对象；主线推进由相关信息／道具／状态收束。挑战不靠长距离折返、无提示穷举、永久丢失唯一道具、强制跳跃或强制等待。实际新玩家试玩时长、迷路／提示使用和完成路径是内容验收依据，不以作者熟练通关或地图像素推定 30—45 分钟。

## V3-5. 技术与素材安排

保留 Phaser 3／TypeScript／Vite，H5 电脑＋手机目标不变，Electron 长期代码保留但不作为每轮前置。旧横版 PlayerMotor／跳跃／承载不强行改名复用；新地面移动、碰撞和室内切换需最小验证。现有进度／幂等、控制 owner 与暂停等可用原则按实际模块适配，不推倒全部业务核心，也不为此先造完整通用引擎。

室内切换是同一章节中的地图切换，章节进度不重新开始。地图／门／返回点／安全锚点身份需一致，切换期间只允许一个权威过程；旧地图自有监听和碰撞回收，目标可用后恢复操作。持久化只存正式稳定进度和安全地点，不存旧 Runtime 事件队列、暂停令牌、输入、速度或全部 Matter 状态。

先让街区、室内、角色和物件在斜俯视中可读；用少量可复用地面／立面／道具模块形成一致风格，再扩内容。旧横版概念图仍是风格／历史参考，不是新斜俯视地图或精灵表。当前不迁移 Cocos／Godot，不新增完整地图加载框架或 Tiled 前置，不买素材／改密钥，不把技术规划当作新架构已经实现。

## V2-4. Demo 应该让玩家做什么

一句话：从解放碑街区出发，为年轻游客找到合适的江岸拍摄位置，沿山城楼梯与木廊下行，用高处观察到的唯一线索开通升降通路，在嘉陵江边完成拍摄分享。

建议首次体验约 5—8 分钟；这是用户测试目标，不是必须拖长的时长。玩家始终知道当前目标，可以在安全街面／阳台短暂驻足和回看，不要求复杂岔路、收集物或多个任务才能产生探索感。

| 区域 | Demo 阶段必须看见和做到 | 不在本次新增 |

| A 解放碑街区 | 用浅色纪念碑主轮廓／钟面、商业立面、连续石质街面建立地点；有足够空间练走与安全短跳，然后前往 B。 | 不以地名文字替代地标；不新增历史卡、商店、教学支线或五屏 A 的硬指标。 |

## 7. Web blur FAIL：检查结论与处置

已读取 [run-Jc0SLc 报告](../test-results/platform/run-Jc0SLc/report.json) 和其事件，而非只看旧总结：
- Web 在 interactive-operation、visibility=visible 时真实 blur，测试将其锁存为非预期中断并 FAIL。
- 原生前台事件 seq 27 指向 ChatGPT；同一报告两个 Electron 平台 PASS。此事实支持该轮失焦来自外部焦点切换，不证明应用有内在崩溃，也不能证明所有 H5 焦点恢复正确。
- 当前 bindPlayerInput 使用 visible＋document.hasFocus() 设置可用性，blur／focus 清理或恢复输入资格；bindVisibilityPause 对真实 hidden 申请独立 Token。可见但失焦与隐藏是不同信号，不能为了测试 PASS 删除失焦保护或强行保持焦点。
- 本轮未做真实按键、标签页切换、失焦恢复专项；本轮 Chrome 首屏可见仅说明已有产物可打开。历史 FAIL 保持 FAIL。

处置：目前没有足够证据认定为应用代码缺陷，不新开“消除 blur”纯测试任务。把 Chrome 正常操作＋真实切页／回焦核对及手机输入中断验证并入首个 H5-01 原型证据，不等美术完成再处理输入问题。若复现持续移动、自动跳跃／交互、对话误提交、输入无法恢复、隐藏追赶或页面异常，再从路线图单独安排最小修复，先复现后修复；不运行 Electron 三端作替代，不用自动重跑挑 PASS。

### 12.2 设备操作与输入来源合并（PROPOSED）

| 动作 | 电脑 | 手机候选控件 | 同一核心语义 |
| --- | --- | --- | --- |
| 左／右移动 | A／D、←／→ | 独立固定左／右按钮 | 只映射已有方向输入，不直接改速度／坐标。 |
| 跳跃 | Space | 跳跃按钮 | 按下、持续按住、松开，复用短按低跳／长按高跳和一次性请求。 |
| 主动交互 | E | 交互按钮 | 单次按压，核心决定目标及可用性，不按住循环提交。 |
| 暂停 | Esc 按 UI 状态路由 | 暂停图标按钮 | UI 请求现有 Lifecycle Controller；不把暂停触摸模拟成可关闭对话的 Escape。 |
| 菜单／完成对话 | 鼠标／现有明确按钮 | 明确的触屏按钮 | 正常完成进入既有入口，取消／系统中断不冒充完成。 |

R 是调试重置，移出普通玩家操作说明，保留调试入口和已有测试用途，不为手机增加 R 按钮。第一版建议不用虚拟摇杆、不新增手柄；混合设备仍可用键盘，显示触控布局不禁用键盘。

输入层建议只在平台侧加入小型动作来源集合／计数：
- 来源至少区分键盘物理 code 与每个 pointerId 的按钮按压；A 与 ← 等同动作也要正确聚合。重复 keydown／repeat、重复 pointerup 不增加计数或重复触发。
- 同一动作有效来源从 0→1 才提交 down；1→0 才提交 up。键盘与触屏、同按钮多指的一个来源释放不能清除其他仍有效来源。换指、取消、销毁的清理必须幂等。
- 采用 Pointer Events 和必要的 pointer capture；分别处理 pointerup、pointercancel、lostpointercapture，旧 pointerId／旧控件代次的尾事件不影响新实例。滑出／换按钮是否换动作先在原型验证，不隐式把拖动做成连续点击。
- 移动与跳跃可同时按；不能让一个“当前手指”变量覆盖其他手指，也不能同时绑定 pointerdown 和 click 给同一游戏动作制造两次请求。
- 维护物理来源与向核心转发边缘即可，不维护第二份“允许跳跃／机关可操作／恢复完成”的业务判断；不复制 PlayerMotor 或新建通用输入框架。
- 对话、恢复、平台禁跳和控制锁由现有协调器裁决；控制锁期间的无效按下不在解锁时自动补发，未放开的来源不能在恢复后伪造新 down。
- 失焦、hidden、旋转、控件隐藏／销毁时释放本触屏层持有的有效输入并取消按压关系。键盘自身失焦清理走既有可用性流程；不得因一层销毁直接释放另一层仍持有的按键。

“清理输入”与“确认真实松开”必须分开：现有 Space／E 的 up 会清除 needsRelease，不能在失焦后无条件伪造 up 绕过 PC-02／交互门槛。须记录取消／丢失和新的接触边缘，验证旧触摸不会恢复，新接触在满足释放条件后可正常工作，不能靠清私有字段、吞掉所有新输入或永久要求双击解决。具体安全接线与顺序交给原型用例验证，不修改核心协议。

短按／长按“效果一致”指两设备遵守同一可变高度规则；不是要求短跳和长跳同高，也不要求不同采样设备的浮点轨迹逐位相等。持续时间、误差容限和设备采样只作为测试条件记录，不重调跳跃参数。

### 12.3 暂停、对话及菜单的边界（PROPOSED）

| UI 状态 | Esc／关闭的建议语义 | 隔离要求 |
| --- | --- | --- |
| 正常探索 | Esc 打开暂停菜单 | 只请求菜单 owner 的 Token，不同时向交互层发送关闭键。 |
| 正在 NPC 对话 | 保留现有 Esc 正常完成对话的语义，并显示清楚标签 | 原已有规则优先，不能为全局 Esc 暂停改掉对话完成；同一输入只消费一次。 |
| 对话中点暂停图标 | 暂停且保留对话 | 不触发 core.closeInteraction，不接取委托；关闭暂停后仍需主动正常完成。 |
| 暂停菜单 | 继续／Esc 只关闭该菜单 | 只释放菜单自身 Owner＋准确 Token；hidden／旋转／RecoveryError 等其他原因仍有效。 |
| RecoveryError／恢复中 | 保留原错误界面和受控按钮 | 菜单不能强制清除恢复锁或伪造世界恢复成功。 |
| 结束／标题 | 明确的再次体验／返回入口 | 不把普通标题当 RecoveryError 页面；重开／退场不越过活动事务销毁门槛。 |

此路由是 Work 推荐方案，尚未冻结新的 UI 操作契约。已有单页对话先增加实际可点击的“完成对话／关闭”入口；若以后采用继续／分页，只有正常完成最后一页才接取，不凭线框图新增页数或 Space／Enter 输入。

菜单、旋转提示若需要阻断模拟，各自使用稳定的独立 Pause Owner／Request Key／Token；通知重复复用原 Token，恢复只释放自身。UI 不直接修改 simulation／physics，不从事件 Inbox 发起暂停。改变布局不改变 Runtime、检查点、业务身份或进度。

返回标题／再次体验的具体运行内语义在 H5-03 下发前按现有路径限缩；不新增存档／取消协议。如果正常退场会触及未完成业务，显示受控等待／拒绝而非清世界或强行终态，不为 UI 顺手重构 MLV。

| 界面 | 共用信息 | 设备差异建议 |

| 通关 | 原完成条件、结果、再次体验／返回标题 | 不新增成就／存档；触屏不依赖 R 或调试重开。 |

沿用 1000×580 逻辑画布和 Scale.FIT 作为候选基线，保持比例、不拉伸，不为手机调整碰撞／世界尺寸。官方 [Phaser 3.90 FIT 说明](https://github.com/phaserjs/phaser/blob/v3.90.0/src/scale/const/SCALE_MODE_CONST.js) 与现有代码支持其保持宽高比的含义；它不自动保证移动端字体和触控目标大小。这里只查阅资料／源码，没有执行移动浏览器测试。

现有 CSS 使用 100vh、上下预留 90px 与最小尺寸，需按实际可用父容器重新核对。建议动态视口高度与回退、safe-area-inset、必要的 viewport 元数据，并处理浏览器地址栏伸缩／软键盘／横竖变化。resize 不重新创建游戏、切地图或重置进度；仅旋转／控件重建清理输入，正常窗口变化不得冒充重开。

建议以独立 DOM overlay 承载触控，按画布显示边界和安全区域布局，避免跟着整个画布缩放按钮。非交互覆盖区不拦截画布指针，按钮区域只消费自身事件；保留已有 Phaser HUD，必要时局部调整字号／换行／位置，不把完整场景 UI 迁出或复制业务状态。

| 元素 | 初始建议（CSS px） | 验证边界 |
| --- | --- | --- |
| 方向 | 56—64 | 实际命中框与多指间距要实测，不能按场景像素计算。 |
| 跳跃 | 68—76 | 支持按住，不能遮住关键落点。 |
| 交互 | 56—64 | 单次触发，禁止无目标时由触屏层臆造目标。 |
| 暂停 | 图形约 44—48 | 图形可小，候选有效触控命中框至少 48，解决与最低命中尺寸建议的差异。 |
| 正文／主要提示 | 实际显示约不低于 14 | 逻辑画布字体要换算为显示 CSS px，不能只写 fontSize=14。 |

上述数值均 PROPOSED／TO_VALIDATE，不是正式工程参数。示例推算：可用区若为 844×390，FIT 的理想比例约 min(844/1000,390/580)=0.672，14 个逻辑像素只约 9.4 CSS px，安全区域还可能减小可用空间。因此 H5-01 就须核对关键提示可读性；完整面板排版留 H5-03，不等全部美术完成才发现触控遮挡。

仅对游戏操作区域／按钮约束 touch-action、浏览器默认手势和事件传播，不对整页无条件禁缩放／preventDefault；对话滚动、菜单和辅助阅读仍可用。不依赖强制全屏、强制横屏、禁用浏览器安全功能或安装应用才能玩。

若采用横屏优先提案，竖屏提示应清理触控并经独立 owner 安全暂停；转回横屏不恢复旧 held，不自动释放菜单／hidden／错误 Token。方向阈值、布局断点、触控显隐及混合设备提示切换仍需原型验证，不只按 UA 判断设备。

### 12.5 首项建议：H5-01 响应式画布与设备输入原型

仅使用现有首关：平台侧小型输入来源合并、固定 DOM 左右／跳跃／交互按钮、可触控的现有对话关闭、基本暂停／继续和画布可用视口。它的可见成果是手机布局与可实际操作的按钮；正式山城美术在紧接的 H5-02，不能连续拆出多个纯输入架构任务。

预计触达现有 web 输入／页面装配／CSS／HTML、必要局部 Phaser 字号／提示及输入适配测试；不修改 PlayerMotor、物理、任务、恢复、平台或通关算法，不接第二地图、不新依赖。具体名单与操作契约在负责人批准后下发单项任务卡，本轮不生成可执行提示词。
