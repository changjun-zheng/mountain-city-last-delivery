## 2. 产品定位与规模调整

沿用 2D 横版平台探索冒险、山城特色虚构立体城市、手绘卡通夜景与 2.5D 建筑纵深，核心体验为跳跃、探索、解谜、发现；不新增第三移动轴、传统战斗或另一套 Windows 核心。

大型半开放仍是边界明确、有主要目标与完成条件的关卡。城市街道连接多层建筑、楼梯、木廊、阳台和建筑剖面；允许按后续具体设计形成局部自由探索、解锁与回访。不是整座重庆一比一复刻、无限地图、无边界漫游或自动引入流式加载。

本次正式替换的是旧小型／紧凑的长期规模目标。清晰引导、环境解谜、独立完成体验、质量优先和有限范围继续保留；“每个现实地标必为一个独立关卡”不作为现行关卡划分约束。具体多少分支、环路、任务、房间、像素和游玩时长均未冻结。

### 首关 MVP 例外边界

- 继续只验收 A 解放碑出生／教学 → B 沧白路与洪崖洞入口 → C 多层吊脚楼向下 → D 低于 C3 的下层嘉陵江岸。
- B 保留全景揭示、年轻游客与唯一核心线索；主动完成对话后自动接取《把山城夜景寄给远方》，靠近或中断不接取，无接取／拒绝弹窗。
- C 只有一个核心机关、一个正确操作，错误可重试且无永久惩罚；成功开放升降路线。D 必须满足委托已接、机关成功、路线开放、指定位置及主动拍摄／分享全部条件，到达不等于通关。
- C3—D 运行时安全范围内有限左右调整、禁跳、禁中途上下；到站停稳对齐后自由上下、无需额外键，释放控制不能覆盖其他 owner 或暂停／恢复保护。
- J1 必经、C3 机关具体摆位、双站自动往返／短停及数值仍按首关原型原状态管理；新增规模确认不替它们作产品决定。
- C-H 外环、J2／J3、收藏／支线／观察／老店主均不加入当前 MVP；外环只能回接 C2，不能绕过 C3／机关、直接进 D、提前开平台或提供第二条核心线索。

扩大最终空间目标不使旧功能切片失效，也不将现有原型认定为完整大型关卡已交付。当前详细空间提案仍需审查，不能把完整版可选内容自动纳入 MVP。

## 3. 内容组织模型（PROPOSED）

`World → Chapter → Level → Area → Segment / Room` 用于产品内容归类，不是已经存在的代码层级或必须一一建类的对象体系。

| 概念 | 建议职责 | 边界 |
| --- | --- | --- |
| World | 虚构城市背景与整体旅程 | 不代表开放世界运行实例。 |
| Chapter | 主题片区与章节内容组织 | 名称、解锁及故事待设计，不直接写进度。 |
| Level | 有入口、主目标及完成条件的可玩地图 | 不必与一个现实地标或 Phaser Scene 一一对应。 |
| Area | 关卡内街区、建筑或楼层 | 首关 A—D 是同一主线的功能区，不拆成四个新关。 |
| Segment / Room | 楼梯、房间、走廊与观景点等局部空间 | 不因有名称就新建独立运行时／Scene。 |

共享 Gameplay Scene 加载不同 Level 可以研究，但当前是专用首关与实验室入口，不把这个建议描述为现成能力；资源加载粒度与 Scene 组织以后用原型决定。

## 4. 完整游戏内容规模（全部 PROPOSED）

建议目标为四个主题章节、六个主要关卡。以下关卡名称只是内容标签，不新建运行时 Level ID，不改变已存在首关 `first-level-night-postcard` 或任务身份。

| 章节候选 | 关卡候选 | 空间与体验方向 |
| --- | --- | --- |
| 第一章：山城初见 | 01 山城夜景之旅 | 现有首关：解放碑、沧白路入口、多层吊脚楼、下层江岸；原任务与谜题保持，详细空间只引用已有原型。 |
| 第二章：老街回声 | 02 老街与坡巷 | 街巷、店铺、生活空间与石阶，探索和轻量环境互动。 |
| 第二章：老街回声 | 03 旧院与屋顶连廊 | 院落、内部通道、屋顶／外部连廊，候选居民故事与发现。 |
| 第三章：山居叠巷 | 04 山腰居民区 | 层叠住宅、山地街道与公共空间，居民生活主题。 |
| 第三章：山居叠巷 | 05 立体连廊 | 多高度连接、公共通道与路线解锁，复用已验证能力。 |
| 第四章：江桥彼端 | 06 江岸与桥下空间 | 江岸、桥下、码头意象及故事收尾；不是已选真实地标或最终剧情。 |

每关 5—8 个候选子区、主线约 15—25 分钟、选做约 5—10 分钟只作估算假设。六关相加主线约 90—150 分钟、含选做约 120—210 分钟；没有试玩依据，不构成工期、内容承诺或验收指标，也不能把首关四功能区强改成八区。

### 关卡内容与玩法循环建议

完整版可沿“进入片区 → 观察建筑／寻找道路 → 平台探索／NPC 互动 → 环境解谜或特色行为 → 获得发现／开放路线 → 完成目标”组织节奏，不要求每关都照搬首关升降平台。

主要路线、少量可选分支、局部回接、多层内外转换、清晰终点是内容建议，不是每关至少一个环路／固定谜题数的强制标准。增加空间应带来新视野、路线选择、互动或回访价值，避免空走廊和为时长增加重复路程。

首关完整版候选沿用 C-H、C-COL-01 风铃纪念章、C-SIDE-01 旧木招牌、C-OBS-01 结构观察及历史卡方向，不新增背包、额外必做目标、收藏数量或奖励。文化观察不是主线解谜资格；已获得收藏／已完成支线将来启用时遵循原永久记录与幂等规则。

## 5. 章节、导航、文化与成长边界

开局不直接用景点选择菜单替代首关体验；未来城市地图、旅行纪念册中的章节导航、解锁顺序、回访入口与完成反馈均 PROPOSED。城市地图是导航候选，不是一座实时开放世界；跨关卡成长不自动引入技能树、二段跳、装备、战斗或新移动能力。

沿用现有任务奖励／探索拾取的文化收藏方向和旅行纪念册方向，但它们不是完整 UI 或通用多关卡任务系统已实现的证据。每项真实建筑、历史、民俗、方言与故事需核对可靠来源；虚构建筑／原创机关不可写成真实设施。第二至四章先做主题与空间，再选择资料参考，不把地标名堆成现实精确路线。

## 7. 概念模块与数据／代码边界（PROPOSED）

| 概念 | 最小职责建议 | 不承担的职责／待验证点 |
| --- | --- | --- |
| LevelDefinition | 平台无关、可校验的关卡描述；候选包括稳定关卡身份、边界、资源引用、出生与锚点、区域、对象、碰撞意图、交互／业务引用、出口及行为键。 | 不是已批准 TypeScript 接口、JSON schema 或新增快照格式；不放 Phaser／Matter Body、DOM、任意脚本或当前 Runtime 事务身份。 |
| LevelCatalog | 静态目录：关卡键到定义引用、章节归属与必要元信息，拒绝重复／未知项。 | 不直接写进度或自行授权进入；解锁规则及“是否可进入”的业务查询由以后明确的进度／导航协作处理。 |
| LevelLoader | 在宿主装配层组织资源、物理适配、视觉及玩法的装配／释放。 | 共享核心不能 import Phaser／文件系统；需拆清纯数据校验与平台资源加载，不把一个巨大加载器放进核心。 |
| LevelBehavior | 特殊机关／路线行为的有限扩展点，适配既有交互与业务协调。 | 不是运行时下载插件、任意脚本执行或另一个 update 循环；普通静态对象无需独立行为类。 |

World／Chapter／Area 等身份是内容组织候选，不自动生成新的全局 ID 协议。空间／对象、目标、奖励、收藏、永久效果、Event／Command／Transaction／Runtime 身份仍独立，不能用编辑器自动数字 ID 取代稳定业务身份；唯一性范围与跨关卡命名约定待设计。

### 数据与代码的取舍

几何、出生、对象摆位、表现引用、对白和已支持的普通交互参数适合数据描述；其有效性、单位、引用与权限仍须检查。支撑、坡面、单向平台、固定步、输入消费、暂停 Owner／Token、事务、进度幂等与恢复属于共享代码。新型机关若共享代码不支持，仍需有边界的行为实现，不能承诺任意 JSON 都能构成新玩法。

“约 80% 内容通过配置”只保留为会话中的愿景，当前没有统计口径／测量，不列 KPI、架构验收或实现效果。候选内容目录可先集中，再按证据拆分定义、地图与实体；本轮不创建 `content/` 空目录／配置文件，不冻结大量 JSON 文件结构。

### 行为时序必须匹配当前核心

会话示例 `create / update(deltaTime) / destroy` 不直接作为正式接口：当前核心的实际固定步、唯一一次物理求解、收集／闭批／仲裁和业务 dispatch 已有顺序。以后行为应接入明确的现有阶段，使用实际固定 Delta 与 Tick；不能由渲染帧调用业务更新、重复 Matter step、递归分发或抢先处理当前阶段新事件。

是否扩充现有 `GrayboxGameplayRuntime`／`afterDispatch` 或提取更清楚的契约需原型验证。行为只申请自己的控制限制／资源，不覆盖别的 owner，不绕过统一事件／命令／事务和结果权限；暂停期间无新模拟 Tick。Registry 若需要，也只允许受信代码中的固定映射，不动态执行关卡字符串。

## 8. 加载、卸载与恢复的候选流程（PROPOSED / TO_VALIDATE）

1. 从受信目录解析选择，验证定义、资源引用、版本、稳定 ID、碰撞意图、出生／锚点与固定快照清单；此时不得开放玩家控制。
2. 由宿主准备本地资源，物理适配器创建临时世界，渲染层创建对应表现；只装配清单内受支持类型，未知必要类型失败关闭。
3. 准备进度与业务协作，按既有初始化语义先应用永久进度／效果，再捕获登记对象的初始完整备用快照并校验；快照准备失败不得开放探索。
4. 完成世界／安全检查与占用基线，绑定输入和平台生命周期；成功后只解除本次初始化 owner 的限制，不能覆盖其他暂停或控制保护。
5. 卸载前先停止接收新输入／行为请求，处理本关仍在运行的捕获锁、临时冻结、恢复和业务关联，再释放自身监听、渲染对象、Body 与资源引用；不得强行释放别的 owner、吞掉 Unknown 或重置身份以逃避未完成事务。

上述是待验证的装配约束，异常时保留旧关还是进入加载错误界面、如何回滚部分装配、输入何时接管、跨关资源复用／缓存、未决事务何时允许切换均未定；不承诺无缝切关或热更新。也不因“大地图”先引入区块流式加载、ECS、插件总线或新的通用引擎。

### 运行身份、进度与检查点的决策缺口

当前核心默认新建运行内进度与业务上下文；宿主重启会新建运行，已有进度对象虽可注入，但不代表已经实现跨关传承。未来切关继续同一 Runtime 还是进入新 Runtime、全局进度由谁持有、旧关未完成命令如何结束／隔离、重新进入如何选锚点，都需要先给出明确语义，不能在本提案暗自选定。

继续遵守现有单一当前有效检查点与完整临时快照、来源／版本／Level 校验、永久与临时分离。不得将旧关快照套用到新世界，或未经新决策建立每关多个可回溯存档槽。失败恢复仍先恢复临时逻辑、再应用永久效果，随后按现有两阶段重建／验证、安全放置与控制门槛；已开路线真实可通行、机关不重解、奖励不重复。资源安全等待、Fail-Closed、有界自动重建和手动重试均不改变。

跨会话存档、浏览器与 Windows 的存档互通、章节／关卡解锁持久化、回访恢复策略与记录迁移尚未实现或确认。不能借地图扩展使用新的本地存储／原生文件 API 或给 Electron 增加 Preload／IPC。

### 容量与大型关卡性能

现有 Inbox、事件历史、命令／结果／事务记录有容量边界，部分命令／事务安全清理尚未具备完整多关生命周期。内容变多可能耗尽容量，不能用无限扩容、丢弃防重记录或复用编号解决。测量 Body／活动对象、图层／纹理、初始化时间、资源释放及记录增长后，再选择有证据的优化；本轮不设帧率、内存、地图面积或容量最终值。

## 9. Tiled 候选与小型验证门槛

Tiled 只作为编辑工具候选，未采用、未安装、未导入地图。官方 [JSON 格式](https://doc.mapeditor.org/en/stable/reference/json-map-format/) 描述 tilelayer、objectgroup、imagelayer 等图层及自定义 properties；[对象说明](https://doc.mapeditor.org/en/stable/manual/objects/) 说明矩形对象原点在左上角。以上是官方格式能力，不是项目导入兼容性已验证；查阅的是当前 stable 文档，不代表项目已选 Tiled 版本或 Phaser 3.90 全功能支持。

候选路径：`Tiled 导出 → 受限格式校验／转换 → 内部关卡描述 → 宿主装配 + 物理／Phaser 适配`。编辑器格式不必直接等同于共享核心契约；目前 Body 配置使用中心坐标，必须验证原点／单位／图层偏移、对象属性、资源相对路径与稳定身份的转换，不能把装饰图层自动全部做成碰撞。

通过小型验证后再决定是否采用；不同时引入 Tiled、另一编辑器和新引擎。无论用什么工具，四层艺术构图、可玩面与背景区分、层次／遮挡仍按美术文档，不保证一次导出就得到手绘 2.5D 效果。外部学习工程／素材清单不是依赖批准，工具和素材授权需分别核实；本轮不下载、复制第三方代码或安装依赖。
