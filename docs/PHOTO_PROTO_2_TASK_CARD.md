## 3. P2-2：修好投影，让构图成为真实维度

### 3.1 现状与缺陷

现有 `composition()` 把主体固定画在屏幕中心，玩家只能前后走改变大小，左右走位对构图毫无影响，`centered` 判定恒为真。

### 3.2 投影规则（2026-11-21 二次修正，本段为最终版）

前两版各自的问题：

- 第一版 `scale × zoom`：主体尺寸只跟固定参数有关，与距离无关，“走远变小”不成立；双楼世界宽 1320 按固定 scale 折算超过取景框。
- 第二版纯针孔投影：修好了尺寸，没修位置。玩家站在建筑南侧时 `dy` 为负，主体被推到画面中心上方，正站即出框。

本版补上俯仰补偿，两者一并解决。

**模型：针孔投影 + 固定俯仰补偿**

```
dx      = subjectCx - playerX
dy      = subjectCy - playerY
d       = max(hypot(dx, dy), 60)          // 下限 60，防除零与无限放大
focal   = 屏幕高 × site.focalRatio          // 每机位独立焦段
k       = focal / d

cx      = 屏幕宽/2 + dx × k                     // 主体中心屏幕 X
cy      = 屏幕高/2 + dy × k + focal × zoom      // 主体中心屏幕 Y，含俯仰补偿

screenW = subjectW × k
screenH = subjectH × k
screenX = cx - screenW/2
screenY = cy - screenH/2
```

**俯仰补偿 `focal × zoom` 的作用与边界**

- 物理含义：相机默认抬头，使“正下方 d 处的目标”落在画面正中
- 玩家在主体正下方时 `dy = -d`、`dy × k = -focal`，补偿精确抵消，正站即居中
- 它只补偿一个固定仰角，**不追踪主体**：横向走位时 `dx` 仍改变 `cx`，构图照样会偏，3.4 第 2 条不受影响
- 不新增朝向／俯仰系统，不加鼠标视角、不加镜头跟随键

**焦段标定公式（新增机位用它算，不要手估）**

```
k_target   = sqrt(目标占比 × 框宽 × 框高 / (主体W × 主体H))
focalRatio = k_target × 正站距离 / 屏幕高
```

**机位参数（1280×720 标定）**

| 机位 | 站位 | 主体中心 | 正站 d | 主体矩形 | focalRatio | 正站占比 |
| --- | --- | --- | --- | --- | --- | --- |
| A 导览楼正面 | `{710, 680}` | `{710, 390}` | 290 | `{500,260,420,260}` | 0.288 | ≈0.30（银） |
| B 木作楼近景 | `{1620, 680}` | `{1620, 410}` | 270 | `{1420,280,400,260}` | 0.326 | ≈0.42（金） |
| C 双楼宽景 | `{1160, 780}` | `{1160, 400}` | 380 | `{500,260,1320,280}` | 0.184 | ≈0.24（银） |

C 用广角（0.184）的理由：两栋楼合并后世界宽 1320，标准焦段在可走走廊（y 540—800）内装不下。换广角是摄影上自然的选择，不是绕过验证。

A 从 0.26 上调到 0.288，是为了让“贴太近”真的看得出来：0.26 时贴近到 d=142 主体顶部只出框 11 px，肉眼几乎无感；0.288 时出框约 28 px、左右也破框，提示才立得住。

### 3.3 评分阈值（按 1280×720 标定，允许 ±0.02 微调）

| 档 | 条件 |
| --- | --- |
| 铜 | 主体完全在框内，占比 ≥ 0.10 |
| 银 | 铜 且 占比 ≥ 0.22，且主体中心在框内中间 1/3 |
| 金 | 银 且 占比 ≥ 0.42 |

### 3.4 必须成立的手感（1280×720 验算值）

1. **站在机位正中** → A 0.30、B 0.42、C 0.24，主体中心 `cy = 360`，完全入框 → 银或金
2. **向左或向右走开 300 px** → A 的 `cx` 从 640 移到 491，超出中心区半宽 96 px，主体仍在框内但出中心区 → 掉到铜
3. **走远 500 px（A 从 d=290 到 d=790）** → k 从 0.715 降到 0.263，占比从 0.30 降到 0.04 → 提示“主体太小”
4. **贴近到可达最近处（A 约 d=142，受建筑碰撞限制）** → `screenW` ≈613 px、`screenH` ≈380 px，框 576 × 324 → 左右与上下同时破框，提示“主体偏出画面”

四条任一不成立，本轮即未完成。这意味着玩家必须真的“找位置”，不能只调大小。

**第 4 条的注意事项**：`d≈100` 位于建筑碰撞体内部，玩家走不到，不要按 100 验算。A 的可达前沿由 `explorationWalls('upper', false)` 与玩家碰撞半径共同决定，实测约 142。
