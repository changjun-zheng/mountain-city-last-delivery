# PHOTO-PROTO-3F：换成整场景底图

## 0. 为什么推翻 3 的分层方案

PHOTO-PROTO-3 的「分层拼贴」有五个问题，逐条修的成本高于换架构：

| # | 问题 | 实测依据 |
| --- | --- | --- |
| 1 | 梯坎是一块实心方板 | `ground_stair.png` alpha=0 的像素占比 **0.0%**，整张不透明 |
| 2 | 建筑周围有暖色方框 | 素材干净：四边 alpha=0、RGB 全零、无淡雾；问题在渲染层 |
| 3 | 地面有 512 网格接缝 | `ground_stone.jpg` 平铺直铺 |
| 4 | 中景 16 栋是两栋重复缩小 | 比例比近景楼还大，地平线与建筑打架 |
| 5 | 地面冷灰 / 背景暖橙 | 两套光照在同一画面 |

改用**一整张预渲染场景图 + 活动前景**。透视、光照、接缝、地平线在生成那一刻就是统一的。这是 2D 游戏的标准做法（预渲染背景 + 活动元素）。

## 1. 新层级

| 层 | 内容 | depth | 随相机 | sway |
| --- | --- | --- | --- | --- |
| 底图 | `bg_scene.jpg`，覆盖整个世界 | **-600** | 是 | **0** |
| 接地阴影 | 每栋楼脚下的椭圆暗影 | `by - 30` | 是 | 0 |
| 建筑 | `bld_house_a/b`、`bld_corridor` | `by`（440 / 520 / 540） | 是 | 0 |
| 道具 | 树、灯笼 | 树按 y，灯笼 2001 | 是 | 树 0，灯笼 1.18 |
| 玩法 | 机位光圈、角色、影子 | 原样不动 | 是 | 0 |
| UI | 取景框、面板、压暗 | 3000 | 否 | — |

**底图的 sway 位移必须为 0。** 它属于 L3 玩法层，一旦跟着摆动，构图判定就废了。

## 3. 新增

### 3.1 底图

`src/photo-prototype/assets/bg_scene.jpg`，1998 × 1180，**已就位**。

比例 1.6932，世界 2200 × 1300 为 1.6923，误差 0.05%，直接铺满：

```ts
image('scene', 'scene', ox, oy, 2200 * k, 1300 * k, 0, 0, -600);
```

缺图时回退到 3 的分层绘制（旧代码保留即可）。

### 3.2 接地阴影

每栋楼底部加一圈椭圆暗影，压在底图之上、建筑之下：

- 中心 `(cx, by + 6)`
- 半宽 = 建筑宽 × 0.46，半高 = 14 × k
- 颜色 `0x1a1a14`，alpha `0.32`
- depth = `by - 30`

没有这层，楼会像贴纸浮在纸上。

### 3.3 台阶对齐

底图里那几级长石阶的视觉位置，要和 `PHOTO_STAIR` 判定区对上。加一个常量：

```ts
const SCENE_OFFSET_Y = 0;   // 可调范围 ±60
```

只调这张图的 y 偏移，**不要改 `PHOTO_STAIR` 的值**（那是玩法判定，已冻结）。

验收标准：角色走到视觉上的石阶时，减速与前倾正好触发；走出石阶范围时停止。

### 3.4 树与灯笼

底图里没有树和灯笼，仍用 `prop_tree.png` / `prop_lantern.png` 叠。树要压到近景，位置按视觉调，锚点底部中心。

## 4. 如果方框仍然存在

换整图后，建筑透出的应该是石板而不是天空，方框大概率自动消失。若仍在，按顺序查：

1. 打印建筑 sprite 的 `depth` 与底图 `depth`，确认前者更大
2. 把建筑 `depth` 临时设成 `10000`，看方框是否消失
3. 消失 → z-order 问题；没消失 → 查 `scene.ts` 第 25 行，`add.image` 的第 4 个参数对 corridor 传了字符串 `'visible'`，那是 **frame 名**，取不到帧时可能渲染异常，应传 `undefined`
