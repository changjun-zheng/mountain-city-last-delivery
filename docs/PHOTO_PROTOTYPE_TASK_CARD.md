## 4. 评分算法

取景框按屏幕坐标计算，不涉及图像识别。

### 4.1 输入

- `viewport`: 取景框矩形 `{x, y, w, h}`（屏幕坐标）
- `subject`: 主体包围盒 `{x, y, w, h}`（世界坐标 → 转为屏幕坐标）
- `frame`: 画面九宫格分区

### 4.2 判定

```
inFrame   = subject 完全落在 viewport 内
coverage  = subject 面积 / viewport 面积
centered  = subject 中心点落在 viewport 中间 1/3 区域

铜 = inFrame 且 coverage >= 0.15
银 = inFrame 且 coverage >= 0.25 且 centered
金 = 银 且 coverage >= 0.35
```

### 4.3 失败反馈优先级

```
if (!inFrame)        → "主体偏出画面"
else if (coverage < 0.15) → "主体太小，再靠近一点或放大取景"
else if (!centered && coverage >= 0.25) → "构图偏了，把主体放到画面中间"
```

### 4.4 参数（可调）

| 参数 | 试制值 |
| --- | --- |
| 取景框尺寸 | 屏幕 76% × 76%，居中 |
| 左右微调步长 | 屏幕宽的 1/12 |
| 机位触发半径 | 64 px |
| 铜阈值 | 0.15 |
| 银阈值 | 0.25 |
| 金阈值 | 0.35 |
| 中心区 | viewport 中间 1/3 |

## 5. 场景内容（程序化，不用美术）

一张 1600×900 的测试场：

- 地面：一块 1600×120 的深灰矩形
- 墙：3—4 块矩形，制造障碍与走位
- 主体 A：由 6—8 个矩形拼成的“吊脚楼剪影”（深褐色），约 420×360
- 主体 B：一根横跨画面的“桥”矩形（深灰蓝），约 900×60
- 机位 1：离主体 A 约 300 px，正面
- 机位 2：离主体 A 约 180 px，需要靠近才能拍满
- 机位 3：离主体 B 约 400 px，能同时框住桥与吊脚楼
- 机位标记：地面一个半透明圆形 + 一个取景角标图标

所有元素用 Phaser Graphics 或 Rectangle 绘制，不使用贴图。

- [ ] 3 格全部铜以上时出现完成文案
